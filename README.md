# Складской учет товаров

Учебная практика УП.02, ПМ.02, задание № 3. Период: 19.10.2026–08.11.2026.

Приложение на Python с Tkinter и MySQL: товары, категории, поставщики,
поступления и списания, текущие остатки, поиск, фильтр низких остатков,
отчет за период и экспорт CSV. Количества целые, в единице измерения товара.
Тестовые записи вымышленные и используются только для демонстрации.

## Запуск

Требуются Python 3.11+, Tkinter, MySQL 8.0.16+ и mysql-connector-python.
Проверено с MySQL 8.4.7, Python 3.12.14 (логика) и Python 3.14 (GUI), Tk 8.6.

1. Создайте виртуальное окружение: `python -m venv .venv`.
2. Установите зависимости в него: `.venv/bin/python -m pip install -r requirements.txt`.
   На Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`.
3. В MySQL создайте пустую базу `warehouse_practice` с кодировкой utf8mb4.
   Выполните `schema.sql`, затем `seed.sql` в этой базе через MySQL Workbench
   или другой SQL-клиент. Повторно импортировать seed.sql в заполненную базу нельзя.
4. Создайте отдельного пользователя приложения с правами SELECT, INSERT,
   UPDATE, DELETE только на эту базу. Учетная запись администратора приложению не нужна.
5. Скопируйте `config.example.json` в `config.json` и укажите свои параметры
   подключения. Файл с паролем исключен из Git.
6. Запустите `.venv/bin/python app.py` из папки проекта.

Для Windows установка Python обычно включает Tkinter. В Linux Tkinter может
быть отдельным пакетом. Не устанавливайте пакеты без согласования с владельцем системы.

## Использование

Сначала заполните категории и поставщиков, затем товары. Выберите раздел
«Движения», нажмите «Добавить» и укажите товар, дату, тип и количество.
Поставщик обязателен для поступления; при списании он не сохраняется.
Дата вводится как ГГГГ-ММ-ДД. Остаток ниже минимума выделяется оранжевым.
Граница низкого остатка строгая: остаток < минимум.

Для редактирования или удаления выберите строку. Товар существующего движения
не меняется: при необходимости удалите операцию и создайте новую.
Связанные справочники защищены внешними ключами от удаления.
Изменение или удаление движения откатывается, если на любом шаге истории
получился бы отрицательный остаток. Операции одного дня упорядочены по ID.

«Отчет о движении» показывает начальный остаток, приход, расход и конечный
остаток по каждому товару за включительный период. CSV содержит текущую
выборку; используется UTF-8 BOM и разделитель `;`. Единицы разных товаров
не складываются в общий количественный итог.

## Структура

- `app.py` — окно, формы, обработка ошибок и экспорт.
- `database.py` — запросы, транзакции и контроль остатков.
- `validation.py` — проверки текста, количества и даты.
- `schema.sql` — структура четырех таблиц MySQL.
- `seed.sql` — демонстрационные данные.
- `test_validation.py` — модульные тесты.
- `tests/test_mysql.py` — интеграционные тесты на отдельной тестовой базе.
- `verification/` — фактические результаты проверки и снимки интерфейса.

## Проверка

`python -m unittest discover -p test_validation.py -v`

Интеграционные тесты запускаются через `python -m unittest discover -s tests -v`.
Они читают `test-config.json` (параметры как в config.example.json), создают
случайно именованную отдельную базу, проверяют функции и удаляют только эту
созданную базу. Нужна учетная запись с правом CREATE/DROP DATABASE для тестов.
Без test-config.json набор пропускается, не обращаясь к рабочей базе.

## Ограничения

Учебная версия рассчитана на небольшой склад. Нет ролей пользователей,
штрихкодов, партий, цен, аудита изменений и нескольких складов. Прямые изменения
через SQL-клиент обходят проверки исторического остатка в Python. Все записи
должны изменяться через приложение. Приложение выполняет короткие запросы
в потоке интерфейса; большие объемы потребуют фоновой загрузки и пагинации.
